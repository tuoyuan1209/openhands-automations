- 配置文件：WORKDIR/config.yaml 是被测机信息的唯一权威来源（host、ssh_user、ssh_port、auth 段、provision 段、mode、测试参数、acceptance 段）。更换被测机器时只修改 config.yaml 及对应 Secrets，不修改本自动化。

- Secrets（OpenHands Secrets 管理）：SUT_SSH_PASSWORD（SSH 登录密码）、SUT_SUDO_PASSWORD（sudo 认证密码）

【认证策略】（适用于所有远程操作）
1. 优先使用 SSH 密钥登录：ssh/scp -i <config 中 auth.ssh_key> -p <ssh_port> -o BatchMode=yes -o ConnectTimeout=10（首次连接用 StrictHostKeyChecking=accept-new）。
2. 密钥认证失败时，先确认目标机器身份（host key 比对 + 登录后执行 hostname 核对），再使用 SUT_SSH_PASSWORD 提供的密码登录（用 paramiko 或 sshpass -f 临时 600 权限文件并在用后删除；密码严禁出现在进程命令行参数中）。
3. sudo 认证：优先 sudo -n；不可用时使用 SUT_SUDO_PASSWORD 以非交互方式认证（如 sudo -S 从 stdin 或临时 600 文件注入，用后即删并 shred/安全删除）；严禁交互式等待密码。
4. 密码与密钥保护：严禁将任何密码、私钥内容写入命令日志、进程参数、配置文件、报告、聊天输出；仅允许引用密钥路径。若任一 Secret 不可访问，立即停止相关操作并报告原因。

【Stage 0 预检查】（每次运行必做；mode=precheck 时到此结束）
1. 配置文件：config.yaml 存在可读，必填键齐全，mode 合法（precheck/full/longtime，缺失或非法按 precheck 处理并在报告注明）。
2. 工作目录：WORKDIR 及 runs/<run_id>/ 可读写（实际写入→读回→删除验证）。
3. Secret 访问验证：在自动化运行环境中实际验证 SUT_SSH_PASSWORD 与 SUT_SUDO_PASSWORD 是否可读取，只输出“可用/不可用”，严禁输出凭据内容；不可用则立即终止运行并报告原因。
4. SSH 密钥：auth.ssh_key 指向的文件存在且可读（权限异常给出告警；仅引用路径，严禁输出内容）。
5. 远程连通性：按上述认证策略（密钥优先、密码回退）非交互登录被测机并执行 hostname，记录远程 hostname 与内核版本。
6. sudo 可用性：先 sudo -n；失败时用 SUT_SUDO_PASSWORD 验证非交互 sudo 是否可用（只输出 可用/不可用）。
7. 基础工具存在性：cyclictest、stress-ng、taskset、mpstat、chrt 是否存在（仅检查，不安装）。
precheck 模式：生成 WORKDIR/runs/<run_id>/precheck_report.md（七项逐项结果、失败详情与修复建议、Secret 可用性结论、红线合规声明），不执行后续阶段，不修改被测系统。

【Stage 1 环境检测】（full/longtime）
通过 SSH 采集被测机：Linux 发行版与版本（/etc/os-release、lsb_release）、内核版本（uname -r）、CPU 拓扑（lscpu、nproc、/proc/cpuinfo）、启动参数（/proc/cmdline 中 isolcpus/nohz_full/rcu_nocbs 实际值，与 config 的 isolated_cpu 比对，不一致标记异常）、中断亲和性（/proc/irq/*/smp_affinity_list 分布，检查是否避开隔离核）、CPU 调度配置（cpuset、CFS 带宽、RT throttling、调频 governor）。小结保存到 runs/<run_id>/evidence/。关键项失败（无法连接、关键工具缺失且无法安装、无权限且无法配置）→ 停止后续阶段并生成失败报告。

【Stage 2 环境初始化】（full/longtime；必须幂等，已配置项自动跳过，严禁重复安装/重复修改；本阶段任一步失败立即终止全部后续测试）
1. 工具检查与安装：逐项检查 cyclictest、stress-ng、taskset、mpstat、chrt；缺失的必要工具使用被测机对应发行版的软件包管理器安装（apt/dnf/yum/pacman，依据 Stage 1 识别的发行版）；已存在且可用的不重复安装。安装失败则终止并报告。
2. 权限检查与配置（仅当 config provision 段允许时执行；每项均：先检查 → 已满足则跳过 → 不满足时备份原文件到 runs/<run_id>/evidence/backup/ 并记录修改内容与恢复方法 → 通过 sudo 配置 → 用新的 SSH 会话重新登录验证生效）：
   a. 实时调度权限：ulimit -r 与 chrt -f <rt_priority> 自检；不足时经 sudo 配置 rtprio 上限（如 /etc/security/limits.d/90-cpu-rt.conf，rtprio 99）。
   b. 内存锁定权限：ulimit -l 自检；不足时经 sudo 配置 memlock unlimited。
   c. /dev/cpu_dma_latency：检查设备节点存在性与当前用户写权限；缺失且允许时经 sudo 创建/放开权限（记录恢复方法）；存在但无权限时在授权范围内配置并记录。
   禁止项：直接配置 NOPASSWD: ALL 的 sudo 规则；执行来源不明的提权脚本；修改 GRUB 及任何内核启动参数；重启或关机被测机。

【Stage 3 CPU 核心隔离测试】（full/longtime；全部经 SSH 在被测机执行；依据 Stage 1 实际拓扑 + config 参数）
保留原有 5 个用例：
a. CPU 亲和性验证：taskset 绑定隔离核/非隔离核，验证实际调度核符合预期。
b. 普通任务调度隔离验证：在非隔离核施加普通负载，验证隔离核不被普通调度占用。
c. 空载实时延迟：cyclictest 绑定隔离核，周期 period_us（默认 1000µs），SCHED_FIFO 优先级 rt_priority（默认 80），时长 duration_s（默认 60 秒）。
d. 高负载实时延迟：stress-ng 打满非隔离核 + cyclictest 同参数 60 秒。
e. 中断隔离验证：/proc/interrupts 前后快照 + 中断亲和性检查，验证中断避开隔离核。
执行要求：所有远程测试进程必须设置 timeout（超时 = 测试时长 + 30 秒余量）；测试期间用 mpstat 周期采集 CPU 利用率；每项结束后立即清理本次启动的远程进程并 pgrep 验证无残留；用 scp（统一连接参数）将完整原始日志回传至 runs/<run_id>/results/（文件名含用例名与 run_id）并校验回传完整性。某用例因环境/权限无法启动时记录原因并跳过，继续其余项；全部无法执行则整体判失败。
longtime 模式：执行长时间实时延迟稳定性测试——cyclictest 绑定隔离核（周期/优先级按 config），时长 long_duration_s（默认 3600 秒），timeout = 时长 + 60 秒；运行期间每 60 秒采集一次快照（mpstat -P ALL、/proc/interrupts、cyclictest 阶段统计）；结束后清理进程并回传全部数据。

【Stage 4 结果分析】（full/longtime）
仅读取回传至 runs/<run_id>/results/ 的真实原始日志：统计各用例实际执行次数/轮次、每个延迟用例的最小/平均/最大延迟（取自工具原始输出）、mpstat CPU 利用率、任务调度行为、中断前后快照对比、隔离效果分析（亲和性是否生效、隔离核是否被普通任务调度、中断是否避开隔离核、空载与高负载延迟对比）。验收判断：依据 config.yaml 的 acceptance 段阈值逐条判断通过/不通过；未设置阈值的项标记“待判定（阈值未设置）”，严禁自行假设阈值。

【Stage 5 报告生成】
在 WORKDIR/runs/<run_id>/ 下生成：
- results/：commands.log（每条用例完整命令与退出状态）、回传原始日志、summary.json（run_id、用例、参数、延迟统计、结论）、summary.csv（每行一个用例）
- evidence/：CPU 拓扑、内核版本与启动参数、中断亲和性分布、延迟统计原始片段、mpstat 统计、权限配置备份与变更记录
- report.md 测试报告：运行编号、环境信息、用例执行明细（含完整命令与退出状态）、原始数据、统计与分析
- acceptance.md 验收报告：逐条验收阈值对照表、总体结论（通过/不通过/中止/待判定）、原因说明、附录（日志与证据路径、实际参数、run_id）
- precheck 模式：precheck_report.md（七项预检查结果与错误详情）
收尾：打印本次运行（run_id）全部交付物文件清单。
